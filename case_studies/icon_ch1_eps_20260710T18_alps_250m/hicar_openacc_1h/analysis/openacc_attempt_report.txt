Conclusion
----------

No HICAR OpenACC executable was produced in this attempt.

The build gets through OpenACC configure, RTE-RRTMGP, Noah-MP, NetCDF detection,
and cuFFT detection. The current blocker is MPI Fortran module compatibility:
HICAR uses mpi_f08 broadly, while the Balfrin cray-mpich-nvhpc/8.1.30 module
available through the MCH environment exposes only mpi.mod.

The NVHPC installation contains OpenMPI/HPC-X mpi_f08.mod files, but the MCH
netcdf-c/4.9.2-nvhpc and netcdf-fortran/4.6.1-nvhpc libraries are linked against
Cray MPICH-NVHPC. Mixing those NetCDF libraries with NVHPC OpenMPI would be an
MPI ABI mismatch and was not attempted.

Reasonable next options:
- Ask whether a Cray MPICH-NVHPC build with mpi_f08.mod exists or can be added.
- Build a consistent NVHPC + OpenMPI/HPC-X NetCDF/HDF5 stack, then try HICAR
  against that stack.
- Add a deliberate HICAR MPI compatibility layer for "use mpi" builds. This is a
  broader code change because HICAR currently uses mpi_f08 types such as
  MPI_Comm, MPI_Request, MPI_Datatype, and MPI_Status in many modules.
